# OBPI-0.34.0-05-activate-standing-taxonomy-gate: Activate Standing Taxonomy Gate

## ADR Item

- **Source ADR:** `docs/design/adr/pre-release/ADR-0.34.0-foundation-sunset/ADR-0.34.0-foundation-sunset.md`
- **Checklist Item:** #5 — "activate-standing-taxonomy-gate: Activate the permanent closure gate: run register-adrs to reconcile the Layer-3 status index after the demotions; wire the --taxonomy gate (closed-kind + terminal-partition assertions) into gz check as the LAST act (wiring equals a terminal tree, so it lands green; anti-staging-flag doctrine forbids wiring earlier over limbo foundations). Seal the registration membrane in the same act: gz register-adrs and first-run gz init both book an adr_created ledger event for any on-disk versioned ADR package without inspecting kind, so a hand-placed kind: foundation package enters Layer-2 truth un-guarded (GHI #706); add a manifest-aware kind check at both ingress points that refuses a foundation package absent from data/foundation_grandfather.json while still booking the grandfathered roster. Depends on OBPI-04's populate + backfill having completed (a naive guard over the empty manifest would refuse all 74). (heavy lane: status-index reconcile, gz check step-registry wiring, ledger ingress guard)."

**Status:** Draft

## Objective

Activate the permanent closure gate — the ACTIVATION half of the sunset, run
only after OBPI-04's migration data + backfill land. Reconcile the Layer-3 ADR
status index to the post-demotion tree (`gz register-adrs`), then wire the
`--taxonomy` gate (OBPI-01's closed-kind / manifest-integrity assertions +
OBPI-03's terminal-partition assertion) into `gz check` as the FINAL act of the
whole Sunset. "Done" is: `gz validate --adr-status-fresh` is green, the
`"ADR taxonomy"` step is present in the `gz check` aggregate, `gz check` exits 0
on the terminal post-migration tree, and the step resolves through the real
check path with no hand-set staging flag gating it.

> **Wiring ≡ terminal tree (anti-staging-flag doctrine).** The gate is wired
> only once the tree is already terminal (OBPI-04 completed), so it lands green
> on first run. Wiring it earlier — over limbo foundations — would force `gz check`
> red, and anti-staging-flag doctrine forbids papering that interim red with a
> hand-set fail-closed flag. Activation is therefore the last act of the ADR.

## Lane

**Heavy** — this OBPI changes the `gz check` step registry (an observable
runtime-contract surface: `gz check` is the canonical quality aggregate humans
and CI run) and reconciles the Layer-3 status index. Heavy-lane Gates 3 (docs),
4 (BDD), and 5 (human attestation) all apply.

**`sensitivity: security`** — the Allowed Paths overlap a registered surface in
`data/security_surfaces.json`: `src/gzkit/quality.py` (`subprocess_user_input`
— the `gz check` runner surface that spawns `uv run gz validate …` subprocesses).
The auto-detect floor is fail-closed on overlap (GHI #625), so this brief
declares `security` and its Gate 5 fires the extended security walkthrough.

## Requirements (FAIL-CLOSED)

1. NEVER wire the `--taxonomy` step into `gz check` before OBPI-04's populate +
   backfill have completed and the tree is terminal. If any foundation is still
   in Pending-with-attested-work limbo, print a BLOCKERS list and halt — wiring
   over limbo forces `gz check` red.
2. ALWAYS reconcile the Layer-3 status index via `gz register-adrs` (never a
   hand-edit of `docs/governance/GovZero/adr-status.md`); the committed index
   must be fresh (`gz validate --adr-status-fresh` exit 0).
3. ALWAYS append `("ADR taxonomy", run_taxonomy_audit)` as the LAST tuple in
   `_build_check_steps()` and register its `_STEP_GUARD_META` entry, so `gz check`
   runs `--taxonomy` permanently on every invocation.
4. NEVER introduce a hand-set staging or fail-closed flag to gate the taxonomy
   step. The step MUST resolve through the real `gz check` path (the same runner
   dispatch as every sibling audit); a flag guard is the anti-staging-flag
   violation this OBPI exists to avoid.
5. ALWAYS make the registration-membrane guard **manifest-aware**, never a bare
   `kind: foundation` refusal: `gz register-adrs` is the canonical regenerator for
   the Layer-3 status index and MUST keep booking the grandfathered roster
   (REQ-0.34.0-02-03). A guard that refuses on `kind` alone would refuse all 74
   and contradict the closure it enforces. Refuse only a foundation package
   **absent from the populated manifest** (GHI #706).
6. Work MUST stay inside the Allowed Paths; denied paths remain untouched.

> STOP-on-BLOCKERS: if OBPI-04 has not completed (manifest unpopulated or backfill
> events absent), print a BLOCKERS list and halt before any write.

## Sequencing

- **Depends on OBPI-04.** This OBPI runs only after OBPI-04's `gz adr demote`
  poolings, manifest populate, and `foundation_grandfathered` backfill have
  completed, so the foundation tree is terminal. The `--taxonomy` gate reads
  OBPI-01's manifest assertions and OBPI-03's terminal-partition assertion; it
  can only land green once the ledger is complete-by-construction.
- **Final act of the whole Sunset.** Gate-wiring is the last step of ADR-0.34.0
  — after it, closure is a permanent, self-maintaining `gz check` gate.
- **Evaluation note — `independence: 1` is inherent, not a defect (operator-ratified 2026-07-12).**
  `gz adr evaluate` scores this OBPI `independence: 1` because it depends on
  OBPI-04's completed migration. That dependency is **real, correct, and required**:
  the anti-staging-flag doctrine mandates the `--taxonomy` gate wire into `gz check`
  as the LAST act (over a terminal tree), so *some* OBPI must be the sequential tail
  that depends on all prior work — no decomposition eliminates it (an earlier 4→5
  split merely relocated the flag from OBPI-04 to here). Per the gz-adr-create §9
  caveat — *"the CLI scorer is a pattern-matching pre-screen, not a truth oracle …
  do NOT reword solely to feed the matcher"* — the score is accepted as a
  false-negative on legitimate sequencing, NOT gamed away. See EVALUATION_SCORECARD.md.

# ADR-0.34.0-foundation-sunset: Foundation Sunset

## Persona

**Active persona:** `main-session` — craftsperson, governance-aware, whole-file-reasoning, direct. Treats a closed set as closed only when its membership is committed, machine-checked, and diff-visible — an implicitly-computed roster is not a closed set, it is a drift surface with better manners. Reads lifecycle from Layer-2 ledger evidence and refuses to read it from frontmatter, because the ADR-0.0.37 investigation proved frontmatter can lie about repudiated work. Distinguishes sealing from deleting: the `foundation` enum value stays valid so the ~51 grandfathered ADRs keep validating, and closure is enforced *around* the enum rather than by amputating it.

Holds two lines under pressure. First: no foundation holding real attested work may be discarded to make the partition tidy — the drop set is computed from net OBPI state, not from a convenient lifecycle string. Second: anti-staging-flag doctrine — the terminal-partition gate wires into `gz check` as the last act of the migration, landing green on a genuinely terminal tree, never green because a hand-set flag papered over an interim red.

This is a capstone, not a feature: it ends an authoring era. That asymmetry earns the two-way-door guard (the golden-file manifest test) so reopening the kind must be a deliberate, reviewable diff rather than a two-line typo.

## Intent

gzkit has authored 74 foundation ADRs (0.0.1-0.0.74) and has matured past its foundation-building era: the identity-shaping invariants that define what gzkit IS are largely in place, and the remaining foundation backlog is going stale (23 foundations sit at 0-COMPLETED-of-N OBPIs (they have authored OBPIs; none completed), many untouched since May). This ADR is the capstone of the campaign's Foundation Sunset movement (Movement IV taxonomy migration, operator-ratified 2026-07-12): it CLOSES the foundation kind to new authoring while keeping it a valid schema value for the grandfathered historical set. The kind is not deleted - deleting the enum value would invalidate ~51 grandfathered ADRs at once - it is SEALED: no new foundation ADR may be authored, and the existing set is partitioned by Layer-2 ledger truth (NOT frontmatter, which the ADR-0.0.37 investigation proved can lie about repudiated OBPIs) into ~51 frozen-historic foundations that stay and 23 genuinely-unstarted foundations (0-COMPLETED-of-N OBPIs — authored but never completed; including storybook ADR-0.0.42 and ADR-0.0.1) that demote to pool, re-promotable later as features. Closing the kind converts the operator's 'no more foundation ADRs' directive from a policy that drifts into a mechanically-enforced standing invariant (gz validate --taxonomy, permanently in gz check) - gzkit's anti-vibing thesis applied to its own taxonomy. Feature kind, not foundation: by its own rule this ADR cannot be a foundation - the act of closing the kind must reach through the feature track. The partition was computed from the ledger (net OBPI state per ADR: obpi_receipt_emitted as completion, obpi_completion_repudiated / obpi_withdrawn / obpi_abandoned as negations, last-event-wins), not from frontmatter status.

## Decision

Seal the foundation kind and partition the existing set, across five design sections (operator-approved) refined by a mandatory design-forcing-function review. INTERFACE: reject 'gz plan create --kind foundation' and 'gz adr promote --kind foundation' at the command layer with three-part guardrail-feedback prose (what failed / why forbidden: kind closed ADR-0.34.0 / next step: --kind feature or pool); extend 'gz validate --taxonomy' (ADR-0.0.17) with two fail-closed assertions - closed-kind (every on-disk kind:foundation ADR must appear in a committed grandfather manifest) and terminal-partition (every manifest entry is terminal via ledger; no foundation in Pending-with-attested-work limbo). DATA FLOW: KEEP the schema kind enum intact (foundation stays a valid value so it validates the ~51 grandfathered ADRs); reuse the existing 'gz adr demote' verb (foundation->pool) for the 23 poolings - no new verb; the terminal check reads Layer-2, never frontmatter. DATA MODEL: data/foundation_grandfather.json with a frozen Pydantic FoundationGrandfatherManifest (extra=forbid) holding IDENTITY-ONLY entries (id, title, semver, frozen_at) and NO lifecycle field - storing lifecycle would bake a Layer-2 fact into a committed Layer-1 file, the exact state-doctrine drift the 0.0.37 frontmatter-lie demonstrated. The mechanism (manifest model, closure validator, demote reuse) ships framework-wide; the DECISION to close is project-local - gz init scaffolds adopters OPEN (early adopter projects are exactly when identity-shaping foundations make sense). OUTPUT: validate exit-0/exit-3 + --json findings array; three new findings foundation_kind_closed / foundation_limbo / grandfather_dangling, each carrying three-part guardrail prose (foundation_limbo explicitly says 'this reads the ledger, not frontmatter - you cannot hand-edit status:Validated to pass; attest via gz closeout'); NO new report verb - sunset accounting emerges from the manifest + gz adr report + ledger demote events. EXTENSIONS: retire ADR-0.0.18's choose-foundation guidance (its record stays frozen-historic; ADR-0.0.17 is extended not retired); coupled-surface coherence sweep (gz-design Step 5 kind question, plan-create/promote help + parser choices, AGENTS.md/CLAUDE.md Kinds table, docs/user/concepts/foundation-feature-invariance-test.md, review ADR-0.0.35); produces a downstream feature ADR re-homing ADR-0.0.37's withdrawn registry->AGENTS.md composition engine (closes GHI #623 superseded); the --taxonomy gate becomes a PERMANENT standing gate, self-maintaining closure, not a one-time migration. REVIEW REFINEMENTS (design forcing functions): (a) the grandfather manifest is protected by a golden-file test pinning it to the sunset roster, so reopening the kind surfaces as a deliberate reviewable diff rather than a two-line typo (a closed set with a freely-editable manifest is not closed); (b) the ledger is INCOMPLETE for pre-ledger foundations (spot-check: 7 of 8 sampled old foundations e.g. 0.0.2/0.0.3/0.0.5/0.0.8/0.0.24/0.0.71/0.0.74 carry NO terminal ledger event), so a pure-ledger gate would false-fire foundation_limbo on half of gzkit's history - resolved by BACKFILL-AT-POPULATE: OBPI-04 emits an attested foundation_grandfathered ledger event per manifest entry, making the ledger complete-by-construction; the terminal-partition gate reads that event (stays Layer-2, honors never-frontmatter), and for pre-ledger foundations the Gate-5 human attestation of the migration is the legitimate witness; (c) demoting 23 foundations renames ADR-0.0.X to ADR-pool.slug, which the ontology (ADR-0.32.0) corpus subgraph tracks, so an ontology re-sense (gz ontology resense) + diff is a Sunset step folded into OBPI-04 to confirm the graph survives with no orphaned lineage or @covers/@surface edges, alongside register-adrs reconciling the Layer-3 status index in the same commit. SEQUENCING: this capstone implements AFTER Sunset steps 1-4 (finish 0.0.65 and 0.0.72; closeout 0.0.54, 0.0.64, 0.0.37) make the tree terminal - the terminal-partition gate cannot wire into gz check while foundations are in limbo, and anti-staging-flag doctrine forbids a hand-set fail-closed flag, so gate registration is OBPI-04's last act (wiring equals populate). Lane heavy: new validator scope, new schema/manifest, new ledger event type (foundation_grandfathered), CLI authoring-rejection behavior. Feature-kind brief-level Gate 5 attestation per ADR-0.0.36 (universal).

## Consequences

### Positive

1. Closure becomes a mechanically-enforced standing invariant: gz validate --taxonomy runs permanently in gz check, so no future agent can author a foundation ADR and no foundation can rot into limbo without a red gate - the operator's directive stops being a policy that drifts. 2. The sunset is PROVABLE: the terminal-partition assertion asserts every foundation is grandfathered-terminal or pooled, with zero in Pending-with-attested-work limbo - a single ledger-computable predicate encodes the whole ruling. 3. Ledger-derived lifecycle (via the backfilled foundation_grandfathered event) kills the frontmatter-trust failure class the ADR-0.0.37 investigation exposed - the gate reads Layer-2, never the frontmatter that lied. 4. The 74 foundations are partitioned by evidence (net OBPI state from the ledger), not by frontmatter status, so no foundation holding real attested work is discarded and no genuinely-unstarted one is retained. 5. Backfill-at-populate makes the ledger complete-by-construction for the grandfathered set, repairing a pre-existing incompleteness (pre-ledger foundations had no terminal Layer-2 event) rather than working around it, with pre-ledger completions witnessed by legitimate Gate-5 human attestation. 6. The grandfather manifest's golden-file guard makes reopening the kind a deliberate, reviewable act - a two-way door that must swing on purpose, not by typo. 7. Reuses existing surfaces (gz adr demote, gz ontology resense, gz adr report, register-adrs) instead of inventing new ones - smallest new surface for the change. 8. Ships the mechanism framework-wide while keeping the closure decision project-local, so gzkit closes its own foundation era without crippling adopter projects for whom foundation-authoring is still appropriate.

### Negative

1. The coupled-surface coherence sweep touches many doc/skill surfaces (gz-design Step 5, plan-create/promote help + parser choices, AGENTS.md/CLAUDE.md Kinds table, the foundation-feature-invariance-test concept doc, ADR-0.0.35 review) - all must move in the same movement or the taxonomy teaches a closed kind as still-open. 2. Implementation must sequence AFTER Sunset steps 1-4; the capstone cannot land its gate green until the closeouts make the tree terminal, and anti-staging-flag doctrine forbids papering over the interim red with a hand-set flag - a real ordering constraint that gates the capstone on prerequisite work. 3. PRE-MORTEM: a freely-editable manifest could silently reopen the kind (someone adds an ADR + a manifest line) - mitigated by the golden-file guard, but the guard itself must not be quietly edited away. 4. PRE-MORTEM: the ledger's pre-ledger incompleteness means the terminal check depends on the backfilled foundation_grandfathered events being correct; a mis-attested backfill would grandfather a non-terminal foundation - mitigated by verifying via existing ledger completions where present and Gate-5 attestation where not. 5. PRE-MORTEM: demoting 23 foundations renames their IDs; the ontology corpus subgraph and the Layer-3 status index both read the foundation set and could be left with orphaned lineage or stale entries - mitigated by the ontology re-sense + diff and register-adrs reconcile folded into OBPI-04. 6. PRE-MORTEM: ADR-0.0.37's re-homed composition feature (GHI #623) may languish unbuilt like storybook did - accepted as SEVERABLE: the sunset freezes 0.0.37 at 15/15 regardless, #623 stays the honest capability tracker, and the renamed gate stops claiming coherence it does not provide. 7. Sealing the foundation kind is a doctrine-identity change: gzkit's taxonomy loses an authoring tier, and ADR-0.0.18 (which taught foundation-authoring) becomes a frozen museum piece - void as instruction while preserved as history; adopters must be clearly told the kind is closed for gzkit but open for them.

## Objective

**router-coverage-completion** (added GHI #522) — Author the 7th `gz-chores` router skill file, route the 16 concrete skills currently unrouted across `gz-chores` (7 chore-flavored) and the existing six routers (9 by natural namespace), re-run `gz agent sync control-surfaces`, and confirm `gz validate --router-tables` returns 0 errors. Closes the "no orphaned high-use skills" gap by making the policy "every concrete skill routed by exactly one router" mechanical.

## Requirements (FAIL-CLOSED)

1. REQUIREMENT: `.gzkit/skills/gz-chores/SKILL.md` MUST exist with valid YAML frontmatter (`name`, `description`, `category`, `lifecycle_state: active`, `owner`, `last_reviewed`, `model: haiku`, `skill-version`) and a `| Intent | Skill |` table that routes exactly these 7 skills: `gz-chore-runner`, `gz-deps-upgrade`, `gz-foundation-triage`, `gz-pythonic-pattern-detect`, `gz-pythonic-pattern-apply`, `gz-check-config-paths`, `gz-cli-audit`.
2. REQUIREMENT: Each of these 9 skills MUST appear in the `| Intent | Skill |` table of its target router:
   - `gz-justify` and `gz-plan-audit` in `gz-workflow`
   - `gz-competitor-radar` in `gz-project`
   - `gz-adr-evaluate`, `gz-migrate-semver`, `gz-obpi-lock` in `gz-governance`
   - `gz-obpi-simplify` in `gz-quality`
   - `gz-issue-file` in `gz-manage`
3. REQUIREMENT: `uv run gz validate --router-tables` MUST return exit 0 with 0 errors after work is complete.
4. REQUIREMENT: NEVER route the same concrete skill from more than one router — uniqueness invariant.
5. REQUIREMENT: ALWAYS bump `skill-version:` (minor — governance procedure change) AND set `last_reviewed:` to today (YYYY-MM-DD) in the same edit for every modified router SKILL.md, per `.claude/rules/skill-surface-sync.md` non-negotiable rule #6.
6. REQUIREMENT: ALWAYS run `uv run gz agent sync control-surfaces` after canonical edits; sync output MUST report no drift between canonical, package copy, and vendor mirrors.
7. REQUIREMENT: NEVER edit `.claude/skills/`, `.agents/skills/`, `.github/skills/`, or `src/gzkit/skills/` directly — those are sync outputs. Edit `.gzkit/skills/` canonical only.
8. NEVER mark the OBPI accepted while scaffold defaults remain in the brief or while `gz validate --router-tables` exits non-zero.
9. ALWAYS reconcile the brief with the parent ADR before implementation begins.

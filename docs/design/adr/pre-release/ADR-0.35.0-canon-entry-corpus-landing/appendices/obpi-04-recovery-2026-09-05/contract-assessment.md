## One current behavioral contract

### Goal and extent

Declare every H1/H2 section `corpus-owned` or `unowned`, maintain a durable unowned-byte floor, and provide one corpus-attested way to change an owned section to unowned and raise that floor. This OBPI supplies the declaration/ratchet/unown facility. Materialization and the rendition-lineage gate retain their existing 05/06 ownership. No split or new general reconciliation mechanism is needed to express the accepted contract. [Brief 73–104, 174–190; plan 9–26.]

### Before/after invariants

1. **Identity and measurement.** One fixed transaction target binds canonical surface identity, source/declaration paths, lock, journal, snapshot, cleanup and ledger witness. A caller spelling that resolves to the same declared file uses that identity; a different or missing file is refused. All source digests and spans use raw bytes without newline normalization. Section IDs use the existing canonical vocabulary; changed heading text with an unchanged ID remains valid. Counts, coverage and histograms derive from the current surface/corpus; authoring-time figures are not constants. [Brief 183–190, 308–309, 868–869, 970–985.]
2. **Declaration and witness coherence.** The declaration covers exactly the live section-ID set with the closed enum. The actual unowned span may be below the witnessed floor after a legitimate shrink; it may not exceed it. The non-null floor witness binds the actual surface, floor and full section map. Replay validates the complete ownership-event prefix from genesis; later genesis rows are inert and re-anchoring is migration-only, without a floor/map change. Existing protections stay in place even where their adversarial tests lie beyond the threat boundary. [Brief 451–453, 714–737, 1135–1139; rulings 693/700/701.]
3. **Ordinary ratchet versus raise.** Recording a total `T <= N` persists `T` and emits the decrease/equality event; `T > N` is refused without changing declaration or ledger. `unown` requires an eligible owned section and nonempty, non-whitespace attestor/reason, changes only that ownership membership, sets the successor floor to `N + measured_section_span`, and records the actual transition. The ordinary helper's absent shared recovery transaction remains the already disclosed 05 sequencing item while it has no production caller. [Brief 304–307, 623–627, 696–699, 1260–1275.]
4. **Exactly one truthful transition witness.** Retry continues the same intended transition and uses its same event identity. An existing ID counts only when its semantic payload equals the expected witness for the actual landed declaration. Recovery never appends a second attestation merely to reconcile source bytes or finish cleanup. [Brief 726–727, 868–870, 1035–1037; manpage 380–391.]
5. **Recovery material is evidence, not canon.** The command retains the measured source bytes for the pending transition; a digest alone is insufficient. It does not silently rewrite the source. Extraction creates an operator-usable copy only after its bytes are validated; newer source edits remain intact. Files required by a live or potentially crash-resurrected journal cannot be deleted or reused. [Brief 1035–1048; plan 186–210, 227–241; manpage 342–345.]

### Accepted failure model and explicit limits

The owned guarantee covers ordinary CLI use, same-surface invocation contention, source editor saves, interrupted writes/retries, disk errors and declaration/journal directory-fsync failure. Tests may inject those failures at production boundaries; they must not need an adversary hand-editing `.gzkit/` to establish an in-scope defect. Arbitrary `.gzkit/` writers are inside the accepted trust boundary; the defense is auditability, and existing defense-in-depth guards remain. [Brief 1079–1146.]

The guarantee is **conditional on the accepted ledger limitations**. #953 owns shared-ledger concurrency/rollback interference and partial ledger records after crashes; #952 owns lack of ledger fsync. They remain disclosed dependencies, not work this OBPI quietly repairs and not reasons to expand its residual to declaration/source/snapshot/cleanup errors. Local tests can use an atomic ledger failure model to isolate the ownership protocol, but passing those tests does not establish real ledger crash durability. In particular, “witnessed/durable” in this contract inherits these explicit ledger qualifications. [Brief 1094–1120, 1206–1243; rulings 699/710.]

### User-visible terminal and pending outcomes

Treat three obligations independently: **W** = the actual transition is witnessed, subject to the ledger exceptions; **R** = the source is reconciled with the measured transaction version; **C** = the current transaction's required recovery cleanup is complete. “Success” requires W+R+C for this transaction, and canonical-loader acceptance at that verification point. A source editor can change the file after return; this is not a promise to prevent subsequent edits or to make progress while the operator continually changes the input. [Brief 1031–1054; plan 156–178.]

- **Fresh precondition refusal:** no declaration/ledger mutation; explain the failing condition, its rule and the usable next step. Do not infer whether intermediate recovery files exist solely from an exit code.
- **A/B/C with source unchanged:** validate predecessor/successor continuity and measured bytes, establish declaration durability even when the replacement is already visible, append the exact missing witness once, establish final source/declaration coherence, then clean up.
- **Source changed with W false:** retain journal and measured bytes, leave newer edits alone, refuse clean completion, and expose a usable extraction/restoration route. Restoring from implementation-retained bytes permits the pending transition to finish.
- **D+E (W true, R false):** report “transition witnessed; source reconciliation pending,” return non-success, preserve the existing witness without duplication, and retain measured bytes plus newer edits across repeated retries. W does not discharge R or C.
- **W+R but cleanup pending:** report the actual storage fault and non-success for the current transaction. Before removing/reusing dependents, prove durable journal absence, including on journal-absent entry. Handle interruption between deletions and residual artifacts after journal disappearance.
- **Journal-absent orphan residue:** first prove durable journal absence. The current plan permits warning and fresh work when only unrelated old residue cannot be removed, while requiring normal declaration validation and durable persistence of the new recovery snapshot. Preserve this classification through finalization; an old orphan cannot become a claimed new-transaction cleanup failure. Never announce a historical transition was witnessed/reconciled just because an orphan exists. [Plan 227–257.]
- **Recovery of a different requested section:** report the recovered transition and terminate the invocation; do not also execute the new request or subsequently claim nothing was written. The current CLI uses exit 1 for this outcome. [Brief 868–870, 913–916; manpage 302.]

The printed recovery sequence must itself be executable from a reproduced failure: save newer work separately, inspect the extracted measured version, restore it intentionally, and retry through canonical-loader acceptance. The command performs neither silent source restoration nor automatic reapplication of an oversized edit. Reapplication is a separate operation and cannot be advertised as universally repairable merely by another unown call. [Brief 1038–1042; plan 220–225, 279–282; manpage 351.]

## Remaining contract-delivery mismatches

These do not require re-deciding span, identity, ledger exceptions, or the three obligations.

1. **Exit prose contradicts its own specified recovery outcome.** Manpage 288 says **“Exit 1 means nothing was written”**, but 302 explicitly includes **“a pending transition for a DIFFERENT section was completed by this run.”** The settled rule is the latter: report the completed recovery and terminate. Correct the blanket explanation, not the behavior.
2. **Coverage persistence wording is genuinely inconsistent.** Brief 189: **“ALWAYS record the coverage figure alongside the ratchet so it can be read without recomputation.”** Plan 43–46: **“The declaration stores the FLOOR ... but recomputes the coverage figure”** and 81–83: **“all derived, none stored.”** REQ07 requires runtime measurement; it does not require an authoritative cached percentage. Current contract above retains runtime-derived measurement. The persisted-versus-output-only wording should be explicitly reconciled in the existing package rather than letting an implementer invent a second authoritative value. This is a narrow documentation/representation question, not a recovery architecture blocker.
3. **Broad slogans need their existing qualifications.** Brief 1107 says **“a section-ownership floor changes only through the governed `gz content unown` path”**, while REQ03 at 305 explicitly permits ordinary decrease/equality updates. Read this with its settled raise-only intent and the disclosed inactive ordinary helper, never as permission to delete the decrease path. Likewise “witness durable” must retain #952/#953 qualifications. The current normalized contract states both explicitly.
4. **Current-plan orphan policy needs accurate provenance and matching delivery.** Plan 245 permits warnings for unrelated residue, whereas manpage 363–368 still globally describes any non-absence cleanup failure as non-success. Separate current-transaction failure from unrelated orphan warnings in documentation if retaining the current plan policy. No missing rulings-log entry by itself authorizes reverting the plan or demands another user ruling.

The protocol is now expressible as one coherent contract. The remaining execution task is to prove its whole lifecycle against final code and deliver that same contract through the brief, plan, diagnostics and manpage; another review round must not be the first execution of these acceptance cases.

## Decisions Made

- **Decision:** Reuse the existing `attested_event` ledger surface for the Step-6 `--attest` emission rather than minting a new ceremony-event type. **Rationale:** BI-2 forbids `--attest` becoming a *parallel emitter*; reusing the surface keeps OBPI-05's collapse a de-dup, not a merge. **Alternatives rejected:** new `ceremony_attested` event type (parallel-emitter, violates BI-2); state-file-only check (Approach A, fails BI-3).
- **Decision:** Gate freshness on event `ts >= run started_at` (datetime-parsed), no nonce/attempt field. **Rationale:** any event emitted during this run necessarily postdates the run start, so prior-closeout / prior-`--restart` receipts are correctly ignored without a schema change. **Alternative rejected:** adding an anchor/nonce field to `AttestedEvent` (unnecessary schema churn).
- **Decision:** Behave coverage waiver for REQ-01..04, deferring end-to-end ceremony BDD to ADR-0.0.63 closeout. **Rationale:** the gate's CLI exit-code/state semantics are proven by REQ-derived unittest (readiness boundary mocked per Unit-tier contract); the genuine end-to-end behave exercises OBPI-01+02+05 together over one full walkthrough — cross-OBPI integration that lands at ADR closeout. Matches sibling OBPI-02 / 0.0.59-03. **Alternative rejected:** authoring a heavy full-ceremony Gherkin now (premature; integration surface incomplete until OBPI-05).
- **Decision:** Inline `_classify_attestation_verdict` rather than import `closeout.py::_parse_ceremony_attestation_text`. **Rationale:** `closeout.py` imports *from* `closeout_ceremony` (importing back is circular) and is outside OBPI-01's Allowed Paths. **Alternative rejected:** moving the parser to a shared module (touches `closeout.py`, scope creep; OBPI-05 unifies the emission paths anyway).

# OBPI-0.0.74-07-mx-awareness-hook: Mx Awareness Hook

## ADR Item

- **Source ADR:** `docs/design/adr/foundation/ADR-0.0.74-mx-mode-maintenance-hangar/ADR-0.0.74-mx-mode-maintenance-hangar.md`
- **Checklist Item:** #7 - "The per-vendor awareness hook — injects the MX banner every turn (load-bearing guarantee); adapts per vendor surface; a liveness check that the hook is wired; tool-output banner as secondary backup; unit tests"

**Status:** Completed

## Objective

While an MX session is open (the marker is present), a per-vendor hook injects the banner
"MX MODE ACTIVE — most guards advisory; gate5_invariants and the PRIME DIRECTIVE still bind"
on EVERY agent turn — a per-turn guarantee, not agent memory. This is the load-bearing nerve
that designs out the OBPI-lock drop: an agent that drifts across edit/read turns still gets the
hangar reminder every turn instead of forgetting it. A liveness check proves the hook is wired,
so a dead per-vendor adapter is a detected defect rather than silent loss of awareness. The hook
adapts per vendor surface (.claude / .agents / .github) the way control surfaces already sync.
A tool-output banner is the secondary backup, never the load-bearing surface.

"Done" = with the marker present the hook emits the exact banner every turn and is silent when
the marker is absent (no-op outside the hangar); the liveness check reports an unwired/dead
adapter as a defect; the adapter is rendered to each vendor surface by `gz agent sync
control-surfaces`; unit tests cover all three behaviors.

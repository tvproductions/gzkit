# OBPI-0.0.38-03-retroactive-classification: Retroactive Surface-Axis Classification

## ADR Item

- **Source ADR:** `docs/design/adr/foundation/ADR-0.0.38-evidence-authority-projection-doctrine/ADR-0.0.38-evidence-authority-projection-doctrine.md`
- **Checklist Item:** #3 — `retroactive-classification` — Classify every existing surface; emit `surface_axis_classified` ledger event per surface; produce `artifacts/audits/surface-axis-2026-05-06.md` baseline.

**Status:** Draft

## Objective

One-time audit pass: enumerate every existing gzkit surface (skills, rules, code-level receipt-emitting modules, validator scopes, CLI verbs, Layer-3 derived views), assign each a function axis (Authoritative / Evidentiary / Projection) with cited rationale, edit the declaration site to record the axis (skill frontmatter, rule body marker, module-level constant, scope registration, parser registration), emit a `surface_axis_classified` ledger event per surface, produce the canonical baseline audit at `artifacts/audits/surface-axis-2026-05-06.md`, and remove the OBPI-0.0.38-02 opt-out so that `uv run gz check` enforces `--surface-axis` going forward.

## Requirements (FAIL-CLOSED)

<!-- Constraints that MUST hold. Numbered list. NEVER/ALWAYS language.
     These are the rules agents ground against. If not met, OBPI fails. -->

1. REQUIREMENT: Every skill under `.gzkit/skills/**/SKILL.md` declares `surface_axis: {authoritative,evidentiary,projection}` in its YAML frontmatter. Skills that produce no decision-influencing output (purely informational scaffolding, ceremony narration) are still classified — likely as Evidentiary if they emit findings, or by self-reference to a parent skill. NEVER skip a skill.
2. REQUIREMENT: Every rule under `.gzkit/rules/**.md` declares the body marker `<!-- surface-axis: <axis> -->` immediately after the rule version marker. Default classification for rule files is `authoritative` (rules bind agent behavior); explicit Evidentiary or Projection requires cited rationale in the audit document.
3. REQUIREMENT: Every Python module under `src/gzkit/**` that emits an ARB receipt OR a fail-closed exit code OR a `passed: bool` field consumed by a caller declares `SURFACE_AXIS: Final[str] = "<axis>"` at module scope. Modules that emit only logging or only data-transformation outputs are not in scope.
4. REQUIREMENT: Every registered validator scope in `src/gzkit/cli/parser_validate.py` (or active equivalent) carries an `axis` field in its registration; default is `authoritative` for all `gz validate --*` scopes unless explicitly overridden with cited rationale.
5. REQUIREMENT: Every CLI verb in `src/gzkit/cli/parser_artifacts.py` and sibling parser files whose default human-readable output an operator acts on declares an `axis` field. Layer-3 derived views (`gz status`, `gz state`, `gz adr report` if it renders ledger projections) classify as `projection`; commands that bind decisions (`gz audit`, `gz attest`) classify as `authoritative`; commands that produce findings (`gz adr evaluate`, `gz plan-audit`) classify as `evidentiary`.
6. REQUIREMENT: `artifacts/audits/surface-axis-2026-05-06.md` is the canonical baseline. It contains a table of every surface (one row per surface) with columns: `surface_path`, `surface_kind` (skill/rule/module/scope/verb), `axis`, `rationale_anchor` (file:line or commit-hash citation), `classifier_decision_quote` (1–3 sentences naming the binding character observed). The audit's row count MUST equal `surface_axis_inventory.enumerate_surfaces()` count from OBPI-0.0.38-02.
7. REQUIREMENT: `data/surface_axis_inventory.json` is a frozen Pydantic-serialized snapshot of the same inventory in machine-readable form, with a `generated_at` timestamp and a `source_commit` field. The JSON file's content MUST be byte-derivable from re-running the enumeration helper — i.e., regenerable, not hand-edited.
8. REQUIREMENT: For each surface classified, a `surface_axis_classified` ledger event is appended to `.gzkit/ledger.jsonl` via the canonical event-emit helper (NEVER hand-write to ledger.jsonl per AGENTS.md § Behavior Rules — Never #2). Event payload: `{surface_path, surface_kind, axis, rationale, classifier, source_commit}`.
9. REQUIREMENT: The `surface_axis_classified` event family is added to `.gzkit/schemas/ledger_events.json` in the same OBPI; no new event family lands without a schema entry.
10. REQUIREMENT: After classification, `uv run gz validate --surface-axis` exits 0 on a clean repo. The OBPI-0.0.38-02 opt-out from the default `gz check` scope set is removed in this OBPI's terminal commit; `gz check` enforces `--surface-axis` from this point forward.
11. REQUIREMENT: `tests/governance/test_surface_axis_baseline.py` asserts: (a) the baseline audit row count matches the inventory; (b) every classified surface has a non-empty rationale anchor; (c) the JSON inventory regenerates byte-identically from the enumeration helper; (d) the count of `surface_axis_classified` ledger events equals the audit row count.
12. REQUIREMENT: When classification is genuinely ambiguous on a hybrid surface (e.g. `gz-plan-audit` produces advisory findings most of the time but exits non-zero on a small set of structural failures), the OBPI MUST split the surface into two declared surfaces (the advisory branch is Evidentiary; the structural-fail branch is Authoritative) OR document the ambiguity with a `surface_axis_undecidable` ledger event naming the named ambiguity, the proposed resolution path, and the GHI tracking the resolution. `surface_axis_undecidable` events MUST be remediated within 30 days; expired events fail-close `gz validate --surface-axis`.
13. REQUIREMENT: For each high-stakes Authoritative classification (any `gz validate --*` scope, any `_enforce_*` function, any schema validator), the audit document includes a "tested-by" anchor citing a regression test that observably fail-closes when the surface's binding behavior is broken. Surfaces lacking such a regression test trigger a follow-up GHI per AGENTS.md § Prime Directive (defects must be trackable).
14. REQUIREMENT: Gate 5 attestation is mandatory (parent ADR is foundation-kind heavy-lane). Operator walkthrough at OBPI close MUST include explicit confirmation of: (a) sample classification of three high-stakes Authoritative surfaces (operator quotes the rationale anchor); (b) Projection classification of `gz status`, `adr-status.md`, and one other named derived view; (c) Evidentiary classification of `gz-plan-audit`, `gz-adr-evaluate`, `advisor()`, and one other named advisory surface. The attestation text cites the audit document by path and one canonical-step ARB receipt name (`arb-step-surface-axis-baseline-*`).
15. REQUIREMENT: `gz agent sync control-surfaces` runs cleanly after all classification edits land; mirrors update without divergence. Skill-version frontmatter is bumped per `.gzkit/rules/skill-surface-sync.md` for every edited skill (minor bump, governance rule change).
16. REQUIREMENT: NEVER classify a surface as `authoritative` without observable evidence of fail-closed behavior. NEVER classify a Projection surface that an existing caller relies on as fail-closed gate input — the caller is the defect, not the projection. Such cases route to either a waiver (when call site is genuinely benign smoke-test) or a follow-up fix GHI (when call site is Boundary-6 drift to be repaired).

> STOP-on-BLOCKERS: if prerequisites are missing, print a BLOCKERS list and halt.

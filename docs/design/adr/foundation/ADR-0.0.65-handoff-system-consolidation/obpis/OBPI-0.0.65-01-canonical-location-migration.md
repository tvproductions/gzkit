# OBPI-0.0.65-01-canonical-location-migration: **canonical-location-migration** — Canonize `.gzkit/handoffs/` as the single handoff write location per ADR-0.0.41. Migrate the 24 per-ADR handoff files (across 10 ADR packages) into `.gzkit/handoffs/`, preserving `continues_from:` chains and frontmatter timestamps. Amend `gz-session-handoff/SKILL.md` output-path doctrine from `{ADR-package}/handoffs/` to `.gzkit/handoffs/`. Bump `skill-version` and `last_reviewed`; run `gz agent sync control-surfaces`.

**Status:** Completed

## Objective

Migrate the 24 per-ADR session handoffs into `.gzkit/handoffs/`, preserving `continues_from:` chain integrity and frontmatter timestamps. Scope is the content migration plus deletion of the now-empty source directories; the orientation reader's dual-scan collapse is OBPI-04 scope and depends on this OBPI completing first.

### Scope Amendment (2026-05-30)

The skill canon amendment originally bundled into this OBPI landed as a direct fix earlier in the same session — `.gzkit/skills/gz-session-handoff/SKILL.md` output-path doctrine has been amended (skill-version bumped 6.3.1 → 6.4.0, `last_reviewed` bumped to 2026-05-30, mirrors regenerated via `gz agent sync control-surfaces`). This OBPI's Allowed Paths no longer include SKILL.md; the Requirements that referenced the amendment (#5, #6, #7) are preserved as non-regression assertions verified by the post-migration test pass. See the `fix(skill):` commit on this session's HEAD for the amendment evidence.

**Duplicate-source dedup (operator decision 2026-05-30).** One of the 24 legacy
sources — `docs/design/adr/pre-release/ADR-0.28.0-focused-context-loader/handoffs/20260524T181428Z-obpi-01-context-core-green.md`
— is **byte-identical** (sha256 `8bcf0c52…`) to a file already present in the
canonical store (`.gzkit/handoffs/20260524T181428Z-obpi-01-context-core-green.md`,
landed in commit `e639710a`). It is an artifact of an earlier ad-hoc partial
migration, not a distinct handoff. Per operator decision it is removed from the
source tree as a dedup (`git rm`) rather than migrated, so the canonical store
gains **23** relocated handoffs, not 24, and the distinct post-migration total is
**34** (11 pre-existing + 23 migrated), not 35. A same-name source whose content
*differed* from the canonical copy would be a fail-closed collision (REQ #9
STOP-on-BLOCKERS); only the byte-identical case is auto-deduped. The migration is
performed by `scripts/migrate_handoffs.py` (REQ #6 reusable migration logic).

## Requirements (FAIL-CLOSED)

<!-- Constraints that MUST hold. Numbered list. NEVER/ALWAYS language.
     These are the rules agents ground against. If not met, OBPI fails. -->

1. ALWAYS: Every handoff `.md` file under `docs/design/adr/**/handoffs/` is moved into `.gzkit/handoffs/` with the original filename and frontmatter timestamp preserved verbatim.
2. ALWAYS: Every `continues_from:` frontmatter pointer that previously referenced a `docs/design/adr/**/handoffs/...` path is rewritten to the new `.gzkit/handoffs/...` location (chain integrity preserved across the migration).
3. NEVER: Leave any `.md` file behind under `docs/design/adr/**/handoffs/` after the migration runs (zero residual files).
4. ALWAYS: Empty `handoffs/` directories left under ADR packages are removed (no residual empty-dir trap for future writes).
5. ALWAYS (non-regression): `.gzkit/skills/gz-session-handoff/SKILL.md` contains zero occurrences of the literal string `{ADR-package}/handoffs/`. The amendment landed via direct fix on 2026-05-30; this REQ asserts the state is preserved through this OBPI's execution.
6. ALWAYS (non-regression): `.gzkit/skills/gz-session-handoff/SKILL.md` `skill-version` is at `6.4.0` (bumped from 6.3.1 in direct fix) and `last_reviewed` is `2026-05-30`. Re-bumping this version inside the OBPI would be a regression.
7. ALWAYS: `uv run gz agent sync control-surfaces` runs clean (no diff in mirror surfaces) after the migration completes — re-verified to confirm content migration produced no incidental skill-mirror drift.
7a. NEVER: Re-touch `.gzkit/skills/gz-session-handoff/SKILL.md` in this OBPI's pipeline execution. The amendment already landed; further edits would be duplicate work or regression.
8. NEVER: Touch `scripts/session_orientation.py`. The `_candidate_handoff_dirs()` dual-scan collapse is OBPI-0.0.65-04 scope; editing it here would collapse the firing-point boundary between briefs (per the ADR-0.0.59 increment-size safety property).
9. STOP-on-BLOCKERS: if a per-ADR source handoff carries an unresolvable `continues_from:` pointer (the target file is missing in both source and destination locations), HALT and surface the broken chain to the operator before proceeding — do not migrate a broken chain into the canonical store.
10. ALWAYS: Work stays inside Allowed Paths; verification commands run as single-program invocations (no `&&`, `||`, `|`, `;`, `$(...)`, or redirects per the OBPI-pipeline shlex contract, GHI #415).

# Claude Opus 5.5 system card: doctrine refresh analysis

**Prepared:** 2026-09-23

**Status:** Analysis for the `frontier-model-card-currency` route and GHI #1089. Reviewed 2026-09-24 against the primary PDF and consumed the same day; see § Review.

**Primary source:** Anthropic, [*Claude Opus 5.5 System Card*](https://www-cdn.anthropic.com/fc1b44717c85dc068bc6ba5024219938094694bd/Claude%20Opus%205.5%20System%20Card.pdf), 2026-09-22, 230 pages. ## Decision this analysis supports

The new card supersedes the Opus 5 card for Anthropic's Opus tier. `data/frontier_model_cards.json` still names Opus 5 as the consumed `current` card. A refresh should re-source or retire each live Opus 5 claim, replace its retained PDF and registry entry together, and preserve the prior generation only in the history surfaces specified by the chore. This analysis is a review input, not a registry rotation or a change to the agent contract.

The most consequential new result is about **where untrusted instructions enter**. The card reports stronger resistance to indirect injection through tool results, while finding that Opus 5.5 can follow instructions embedded in third-party text pasted by a user into their own message. The current gzkit rule distinguishes the *channel* (user turn versus tool output); the new evidence says a user turn can itself carry externally authored text. The refresh should preserve the operator's authority while making the origin of pasted material explicit. This is a proposed reading of the card and the current rule, not an observed gzkit exploit.

The registry's `governance-core.md` path needs reconciliation against the current tree before treating its list as complete.

The refresh should check every *live* claim on those surfaces, including the model-selection mapping, not merely replace the model name. In particular, the Opus 5 quotation about constraint adherence, the old adaptive-injection percentages, the fallback description, and Opus 5 effort peaks are generation-specific. Historical Evolution/Origin entries and `docs/governance/rule-version-history.md` are dated lineage, not live operating guidance. The current Fable/Mythos 5.1 and GPT-5.6 citations have their own source lifecycles; this analysis makes no claim that they rotate with the Opus tier.

## Proposed acceptance evidence for the refresh

1. Retain the Opus 5.5 primary PDF in `data/system_cards/` and verify its hash. Replace the Opus 5 registry entry and retained PDF in the same change, after live Opus 5 claims are re-sourced or retired.
2. For each changed doctrine sentence, record the Opus 5.5 section or a separate current source that supports it. Mark earlier-snapshot and product-mitigation results as such, and keep the Shade and Gray Swan denominators separate.
3. Verify the rendered rule consumers (`CLAUDE.md`, rule mirrors, skill wording, and the scorecard) after any canonical edit using the repository's control-surface sync and document validation paths.
4. Check that a reader can distinguish an operator's direct instruction from an instruction inside externally authored text pasted by that operator, without demoting operator-authored repo canon.

**Boundary:** This analysis does not run a model comparison in gzkit, change a threshold, grant work authorization, or consume the card. It prepares the evidence and identifies claims to adjudicate in GHI #1089's refresh.

## Review (2026-09-24)

Every figure, denominator, section and page reference above was checked against the retained PDF (`data/system_cards/anthropic-claude-opus-5-5-2026-09-22.pdf`, same SHA-256). Printed page numbers equal PDF page numbers. Most claims hold. Four do not, and the doctrine refresh follows this section rather than the table where they differ:

1. **The fabricated-approval incident is not an earlier-snapshot result.** § 6.3.1 (p. 102) reports it for "other Claude Opus 5.5 snapshots", and the card's external-review note (p. 96) says these monitoring findings are now attributed across the released model's snapshots rather than to earlier ones. The < 0.01 % figure is the rate for the whole overclaiming-user-intent category; the fabricated quote is one instance within it.
2. **A released-model regression is missing.** The card lists more often accepting unverifiable claims of authorization as a regression (p. 3; § 6.4.1, p. 105). It bears on the authorization boundary and is carried into `untrusted-content.md` and `agent-contract-rationale.md`.
3. **Figures across cards do not compare.** The Opus 5 Gray Swan pair quoted in the table (0.4 % / 4.8 %) is the Opus 5.5 card's re-run under a revised setup; the Opus 5 card's own figures differ. Doctrine cites each figure with the card and section it came from.
4. **Two limits on § 6.5.1 belong beside its numbers:** the product-mitigation zero was measured at default effort only, and the card says the evaluation measures an egregious subset of pasted-text attacks, from coding scenarios only (p. 96).

The review also found a defect in the doctrine this analysis was preparing to replace: two quotations the live docs attributed to the Opus 5 card's § 8.4, a remedy that "recovered performance on most of these tasks" and a tendency to "make more changes than the task requires", are not in that card's text, whose § 8.4 carries scores and figure captions only. They were retired in the refresh rather than carried forward.

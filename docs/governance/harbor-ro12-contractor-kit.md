## Scope

RP-12 lands the governed apparatus for maintenance work: the positions, kept apart by mechanism; the records of what was isolated, done and left outstanding; the inspection independent of the performer; the runtime that drives each act; and the closure a reviewer witnesses. It keys on RP-5's work-package id and extends the runtime RP-14's tranche 1 moved to the work-package surface, as `kind: repair` (RP-14 ruling 4: one runtime, `kind` selecting the procedure).

The test for the design inside the drydock is the maintenance discipline, not canon's ceremony. Safe mode suspends canon and does not suspend that discipline (record decisions *the design review is judged from the drydock's side* and *the maintenance discipline is the drydock's own*).

It does not land the two-way mode contract across existing controls, which is RP-13, or `gz obpi`'s removal, which is RP-14's tranche 3. The pipeline is carried forward unchanged: lessons cross each way as GHIs.

## The cwd-escape guard (#1296)

The issue's acceptance cases, unchanged by ruling, are requirements of this package, landed by O1 (ruling 25):

1. A dispatch meant for a throwaway project whose shell is left at the repo root, running a ledger- or canon-writing `gz` verb, is refused before any write, and the ledger line count is unchanged.
2. The same verb run where the dispatch intended proceeds (the valid control).
3. A main-session `gz` command run by the operator in the live checkout is unaffected (second control).

Each is shown by a test that fails if the guard is removed, and one of the three against a real dispatched subagent. The harness facts are in the contract's § Rulings of 2026-11-02. #1296 closes as superseded by this section, which is the requirement's one home (operator, 2026-11-03, verbatim: *"A"*); the guard is built and not yet accepted: the verb refusal (ruling 36), each case shown against `gz wp dispatch` in `tests/commands/test_wp_run.py`, and the stamp hook (rulings 34, 35, `.claude/hooks/dispatch-stamp.py`), shown on fixture transcripts and ledgers in `tests/test_dispatch_stamp_hook.py`. The three cases against a real dispatched subagent, with the red witness, are § The dock trial, flown 2026-11-05. The limits stand in the open, measured at the hook's independent review: a hook that cannot run at all, `uv` failing, a timeout or a payload that is not JSON, leaves the call unstamped, since Claude Code proceeds past a failing hook; a dispatch line copied into another prompt gives that subagent the dispatch's root, ruling 1's copy limit; and the match reads command words, so a `gz` built at run time (`$(echo g)z`, `g''z`) passes unstamped, ruling 34's limit. Measured at the hook's second review: the refusal holds only in a `gz` that carries it, so a stamped call whose `gz` resolves to another install passes unchecked, as `uv run gz` outside this project resolved to a uv-tool install of py-gzkit 0.34.9 predating ruling 36, until a release carries the guard; and under ruling 38 a dispatched subagent whose prompt lost its dispatch line, forgotten by the coordinator, not passed to a helper subagent, or mistyped, would be held to the project's root and not its dispatch's.

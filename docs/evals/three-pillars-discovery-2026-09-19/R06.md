The cause is an attribution guard based on prior staging, not on the content the ceremony will commit. No failed commit is needed.

Impact account: ordinary edits enter the working tree/index; `commands/sync.py::_execute_git_sync` stages them with `git add -A`; `_commit_staged_changes` writes a generated chore message containing `Task: TASK-gz-git-sync`. That durable Git record attributes substantive work to the ceremony. `_build_sync_commit_message` also lists governance anchors and recent ledger events, but those best-effort summaries do not restore the work’s own attribution.

The downstream checks explain the apparent success. `validate_commit_trailers.py::_validate_commit_trailers` accepts any valid Task trailer for `src/` and `tests/`; `tasks.py::has_task_trailer` accepts this ceremony slug. The configured prepare-commit-msg hook explicitly preserves an existing trailer, so it cannot repair the attribution. Formal TASK discovery through `validate_task_envelope.py::_commit_trailer_channel_for_obpi` uses `parse_task_trailers`, which extracts formal identifiers, not the ceremony slug. Thus syntactic compliance can coexist with lost TASK-to-work linkage.

The governing boundary is `.gzkit/rules/tests.md`’s distinction between direct-fix/formal TASK attribution and ceremony attribution for bundled surface synchronization. Trust doctrine requires provenance behind labels; state doctrine makes ledger events authoritative for completion, so a successful commit must not be interpreted as completion evidence. Tool/skill/runbook alignment requires the documented preview and execution to agree.

Evidence of the hole:

- `_staged_governed_paths` reads only `git diff --cached --name-only` and fails open on inspection errors. Unstaged modifications and untracked files are invisible.
- `_execute_git_sync` invokes that guard only inside `dirty and auto_add`. `--no-auto-add` still reaches `_commit_staged_changes`, providing another route for already-staged substantive work.
- `_detect_stranded_commit_message` protects a different condition: a previous conventional commit message left in COMMIT_EDITMSG. With no attempted commit, it supplies no protection.
- `test_sync_sweep_guard.py::test_empty_index_still_sweeps` explicitly accepts an empty index, but models no working-tree content. It therefore does not distinguish harmless pending synchronization from ordinary unstaged source work.

Smallest complete repair: strengthen the existing ceremony admission boundary, retaining its documented `src/` and `tests/` attribution scope.

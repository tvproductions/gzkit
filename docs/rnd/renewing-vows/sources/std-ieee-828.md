## Scope (paraphrased)

The standard sets minimum requirements for configuration management (CM) processes in systems and software engineering, for any form, class or type of software or system. Its predecessor had defined only the content of a software CM plan. The 2012 revision also explains CM itself: identifying and acquiring configuration items, controlling changes, reporting the status of configuration items, and software builds and release engineering. It says which CM activities are done, when in the life cycle they happen, and what planning and resources they need. The P828 page restates this scope. It adds that the standard supports ISO/IEC/IEEE 12207:2008 and 15288:2008 and uses ISO/IEC/IEEE 24765 terminology.

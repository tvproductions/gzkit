# `.claude/rules` re-audit: does each rule bind at the moment its glob fires? (read-only, 2026-11-08)

The test applied to each rule: a path-scoped rule loads on Read, Write or Edit (or cat/head) of a matching file. It never loads on Bash, on commit, or at session start, and once loaded it stays in context. A rule earns its glob only if its content governs the act of editing the files that glob matches.

How the evidence was gathered:
- All 27 rules were read in full in the first pass.
- Coupled consumers were found by grepping `src/`, `tests/`, `data/` and `config/` for each filename, then reading the hits that open the real rule file.
- I read the code that audits the rules: `gz validate --advisory-scorecard` (`trust_audits/release.py`), `canonical_rule_files` (`validators/rule_version_markers.py`), `gz validate --distribution` (`trust_audits/distribution.py`), and the mirror and nested AGENTS.md renderers (`src/gzkit/rules/__init__.py`).
- "Names rule" means the failure message itself cites the rule path or section, as opposed to a docstring or comment.
- Bytes are measured section sizes from the first pass. "Kept" figures are rounded to about 100 B and count the version banner the rule must keep.

Moment codes used in the table:

| Code | Moment |
|---|---|
| E | editing a matching file |
| D | design or authoring decision |
| S | shell command |
| C | commit |
| Ss | session-level |
| R | review, audit or ceremony time |

## Rule-retirement policy

**gzkit has none for rules.**
- `skill-surface-sync.md` § Retirement policy (delete-on-retire, GHI #464) is scoped to skills only: "A superseded or consolidated skill's directory is deleted from every surface root".
- Rules have no `lifecycle_state`, no retired-slug filter in `gz init` or `gz upgrade`, and no mechanism that removes a retired rule from an adopter's `.gzkit/rules/` or vendor mirror. I searched `src/gzkit/rules/`, `init_cmd.py` and `upgrade.py`; skills have `lifecycle_state: retired` filtering at `init_cmd.py:1059`, rules have nothing equivalent.
- The only precedent is ad hoc: `governance-core.md`, retired 2026-09-17 (GHI #921, operator "it all seems pretty ad hoc, do option A"), recorded in `advisory-rules-audit.md` § Governance Core. Its binding clauses were folded into AGENTS.md. The scorecard heading kept the former path because the grandfather keys derive from it. Its Coverage Ledger entry was removed, and its rows kept their numbers.
- Retiring rules therefore needs, first, a rule-retirement clause. It would sit beside the skill one and say: delete from every surface; remove the distribution-baseline entry; remove the Coverage Ledger entry and re-point the `source=` rows; re-point violation messages; handle the adopter copy.
- The adopter-copy gap and the silent ledger orphan should be filed as defects (GHI via `ghi-author`).

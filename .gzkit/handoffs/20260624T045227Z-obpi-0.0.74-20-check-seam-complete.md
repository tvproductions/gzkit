The work routed the ~37 `gz check` audit steps through the MX checkpoint at ONE

seam, not ~30 inline substitutions" design.

## Important Context

- **Seam-only design (item 20 / REQ-02).** The solo `gz validate` handlers
  (`--qc-binding`, `--fidelity-presence`, `--waiver-ratchet`, `--unscoped-rules`,
  `--evaluation-justify-binding`) are NOT modified. Within `gz check` they run as
  subprocesses whose `returncode=3` is captured by their `run_*_audit` wrappers
  into a `QualityResult`, which the single `_apply_mx_seam` call routes through
  `checkpoint.resolve`. This is why `src/gzkit/quality.py` and `validate_cmd.py`
  were never touched.
- **Scope narrowing at Stage 5.** The brief originally over-declared
  `src/gzkit/quality.py` (a registered `subprocess_user_input` security surface)
  and `validate_cmd.py` in Allowed Paths. `gz obpi complete` tripped the
  security floor on that declared-but-untouched overlap. Resolution: narrowed
  Allowed Paths to the actually-touched files (`git diff` is the proof), moved
  the two untouched files to Denied Paths with rationale. The security overlap is
  genuinely absent after narrowing — NOT waived. Improvement insight logged to
  `.gzkit/insights/agent-insights.jsonl`.
- **Tuple shape preserved.** `_build_check_steps()` stays a 2-tuple
  `(name, runner)` so the 3 consuming tests that unpack `(name, _)` are
  unaffected (`test_closeout_proof_view.py`, `test_surface_fidelity_composite.py`,
  `test_complexity_doctrine_links.py`). Guard metadata lives in a separate
  `_STEP_GUARD_META` dict.
- **Defensive `getattr` in the seam.** `_apply_mx_seam` uses
  `getattr(result, "returncode", 0)` so the `SimpleNamespace` mock runner in
  `test_progress_indication.py` passes through unmodified.

## Decisions Made

1. **Separate `_STEP_GUARD_META` dict, not a 4-tuple** — rejected widening
   `_build_check_steps()` to `(name, guard_name, level, runner)` because three
   consuming tests unpack `(name, _)` and are outside Allowed Paths. Rationale
   recorded in the plan's destination-in-mind disclosure.
2. **Seam-only, no per-runner edits** — per ADR item 20 / REQ-02. The seam in
   `check()` covers both the quality.py wrappers and the validate_cmd solo
   handlers via the subprocess-returncode funnel.
3. **Narrow rather than waive the security floor** — `git diff` proved
   `quality.py` untouched, so narrowing Allowed Paths is the honest fix vs.
   `--accept-security-floor`.

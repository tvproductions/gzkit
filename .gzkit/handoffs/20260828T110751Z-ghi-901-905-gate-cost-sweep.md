## Important Context

Scheduling is exhausted; the gate is contention-bound, not schedule-bound. Behave costs 29.17s alone and 46.5s when overlapped with Test (+17.3s); Test pays only +3.2s. The floor is Behave's contended runtime plus Docs build, roughly 46-50s. Going below that means making Behave or Test faster, not reordering them. Behave is single-threaded over 443 scenarios with no native parallelism and runs unfiltered on purpose (operator ruling 2026-08-26).

The reuse fingerprint keys on the INDEX tree, not the working tree or HEAD. Any staging change between `uv run gz check` and `git push` invalidates it and costs a full re-run with no warning. This session paid 71.6s once for exactly that: `git add -A`, check, then `git restore --staged` to split a commit. Stage everything, check, commit, push, and do any commit-splitting BEFORE the check.

`uv run gz check --fast` is 9.9s against 71.6s full and skips only Test, Behave and Docs build. Both failures this session's full runs surfaced (tautological-test audit, format) are inside --fast's scope, so 143s of discovery was available for 20s. Iterate on --fast or a single `gz validate --<scope>` (0.2-1.7s); pay the full gate once, immediately before push.

The `verifier-pipe-gate` PreToolUse hook refuses any canonical verifier in a non-final pipeline stage. Use `set -o pipefail` or redirect to a file. It fired four times this session and was correct every time.

The tautological-test audit flags any function combining a filesystem op with an assertion and no production call. It rejected the first draft of an assertion helper that took a path and called `.stat()`. Assertion helpers should take already-observed VALUES, leaving `stat`/`access` at the call sites that drive production code.

Chore scripts are mirrored: `.gzkit/chores/**` is canonical, `src/gzkit/chores/**` is the wheel mirror regenerated by `uv run gz agent sync control-surfaces` and pinned by `uv run gz validate --distribution`. Editing the mirror alone drifts the gate; this session edited the mirror first and had to re-seat the change canonically.

Windows has neither an execute bit nor a metadata-change time. `os.chmod` carries only the read-only attribute (every writable file reads 0o666), and `st_ctime` is the CREATION time, so it moves for neither a write nor a chmod. Any probe asserting `0o755` or using ctime as a write witness is unobservable there by construction.

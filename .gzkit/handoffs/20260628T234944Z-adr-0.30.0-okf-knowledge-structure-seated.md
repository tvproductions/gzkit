## Important Context

- **ADR-0.30.0 seats TWO coupled concerns the operator ruled into one ADR.**
  (1) The OKF documentation-knowledge structure (a typed, domain-named
  OKF-conformant markdown bundle for agent orientation), and (2) the `docs/` vs
  `.gzkit/` content boundary. They are coupled because OKF cannot home a bundle
  correctly until the boundary decides where gzkit-core knowledge lives.
- **OKF ≠ CMS (operator's own framing).** ADR-0.16.0 (cms-architecture-
  formalization) governs **control-surface rendering** (the Django-parallel
  headless CMS). ADR-0.30.0 governs **documentation/knowledge-base orientation
  for agents**. Orthogonal concerns, distinct consumers. Do NOT route OKF work
  under ADR-0.16.0.
- **OKF is a real external standard** (Google Cloud / GitHub, v0.1). Verified
  against the actual spec this session: required frontmatter field is `type`
  ONLY; other fields optional; unknown fields and unknown `type` values are NOT
  errors; bundles are **domain-named, never format-named** (the spec's example
  root is `sales/` — there is no `okf/` namespace); `index.md` =
  progressive disclosure, `log.md` = history, markdown links = graph edges;
  **orientation layer, NOT a truth/authority source.**
- **The content boundary is "a delicate matter" (operator).** gzkit-core canon
  and the binding canon of documentation belong under `.gzkit/`; `docs/` is
  reserved for adopter-authored content. Consequence: much of gzkit's current
  `docs/` core canon belongs under `.gzkit/`. **The wholesale `docs/` → `.gzkit/`
  migration is DECLARED as a phased consequence, NOT performed by this ADR.**
  OBPI-06 authors the boundary doctrine and asserts no migration is performed
  (REQ-06-03). Do not start the migration without explicit operator direction.
- **"We don't do foundation any longer" (operator ruling, 2026-06-28).** New
  ADRs go to `feature` kind, not `foundation`. This aligns with Movement IV's
  "abolish foundation" item; the operator ratified the stance now.
- **No mechanical content-boundary validator was added — deliberately.** A
  fail-close check would break the repo today (most core canon still sits under
  `docs/`). The boundary is doctrine + a Boundary Invariant audited at closeout,

## Decisions Made

- **Decision:** Reconcile the two stale Movement II checkboxes rather than
  re-implement.
  **Rationale:** the kind-blind behave gate was already shipped (GHI #636); the
  remaining-cut-order item duplicated Movement IV and contradicted the reductive-
  deferral ruling. Re-implementing existing work is vibing (Behavior Rule #9:
  surface the inconsistency, do not silently re-implement).
  **Alternatives rejected:** writing new exemption code (already exists);
  executing cuts #4/#5/#6 now (sequenced later by the campaign).
- **Decision:** OKF gets its own feature ADR-0.30.0, distinct from ADR-0.16.0.
  **Rationale:** the intent test — ADR-0.16.0's declared intent is the control-
  surface CMS; it never named documentation-knowledge OKF conformance, so OKF is
  a new capability, not corrective work under 0.16.0 (operator clarification).
  **Alternatives rejected:** route under ADR-0.16.0; rendition-repair lineage.
- **Decision:** Fold the `docs/` vs `.gzkit/` content boundary INTO ADR-0.30.0
  as a feature concern (not a separate foundation ADR).
  **Rationale:** operator ruling ("this is part of 0.30.0") plus "no foundation
  any longer." The boundary is the territory the OKF map sits on.
  **Alternatives rejected:** separate foundation ADR; separate feature ADR;
  design-dialogue-only.
- **Decision:** No `okf/`-named folder; bundle root is domain-named at
  `.gzkit/governance/knowledge/` (a dedicated sub-root, separate from the
  pre-existing `.gzkit/governance/ontology.json`).
  **Rationale:** the OKF standard names bundles by domain, never by format; the
  sub-root keeps the generated bundle separable from existing ontology files.
  **Alternatives rejected:** `.gzkit/okf/` (format-named, validator-incompatible);
  flat `.gzkit/governance/` (collides with ontology files); `docs/okf/`.
- **Decision:** CLI verb `gz knowledge` (not `gz okf`); validator flag kept
  `--okf-conformance`.
  **Rationale:** extend the no-format-naming principle to the verb (verb +
  package `src/gzkit/knowledge/` now agree); but the flag names the external
  standard the bundle is *checked against*, so `--okf-conformance` is precise.
  **Alternatives rejected:** keep `gz okf`; rename flag to
  `--knowledge-conformance` (would obscure what it validates).
- **Decision:** Keep the no-enforcement-evidence rule as a STRUCTURAL-FENCE REQ
  (REQ-0.30.0-03-05) proven via an ADR `## Boundary Invariants` entry.
  **Rationale:** "OKF never enforcement evidence" is a cross-OBPI boundary
  property, not a unit-testable behavior — STRUCTURAL-FENCE is its only honest
  proof channel (ADR-0.0.59); the OKF standard itself says OKF is not authority.
  **Alternatives rejected:** a BEHAVIOR test; its own OBPI.
- **Decision:** Route the orphan-ledger finding to GHI #584, do not file a new
  GHI.
  **Rationale:** Step-0 prior-art lookup found #584 already tracks this exact
  class (233 orphaned events, 0.27.0–0.51.0, OBPI-0.30.0 listed). A fresh issue
  would be a sibling-cut duplicate.
  **Alternatives rejected:** file a new GHI; leave untracked.

## Important Context

### Token-Block Doctrine (Parent ADR ADR-0.0.41)

This OBPI is part of the token-block lock-discipline foundation ADR. The doctrine is: **A token cannot be surrendered without a register entry.** OBPI-02 closes the check-then-write race condition in lock claiming and introduces the `--abandon` flag + degenerate-handoff writer, staging the warning-only behavior before OBPI-03's fail-closed flip. OBPI-03/04/05 depend on OBPI-02 landing first.

### Brief Format vs. Reconcile Tool

The brief's Acceptance Criteria section properly declares 9 REQs with the pattern `- [ ] REQ-0.0.41-02-0N [KIND]: ...`. The reconcile tool's req_count=-9 suggests either:
1. The tool expects a different section structure (e.g., a dedicated `## Requirements` section distinct from `## Acceptance Criteria`)
2. The tool has a regex pattern that doesn't match the current brief format
3. The newly authored brief is missing metadata that the tool looks for

**For operator/next-session:** Check the reconcile tool's source code (likely in `src/gzkit/commands/brief.py` or `src/gzkit/brief_*.py`) to understand why it can't parse the REQs, then either amend the brief format or file a GHI if the tool has a bug.

### Governance Gate Timing

The `gz obpi pipeline` command invokes `gz brief reconcile` as a precondition check. The drift means the pipeline won't start Stage 2. This is a **fail-closed safety feature** — the pipeline requires brief state to be clean before implementation begins. This is correct behavior; the issue is that the drift is a false positive or the brief format doesn't match the tool's expectations.

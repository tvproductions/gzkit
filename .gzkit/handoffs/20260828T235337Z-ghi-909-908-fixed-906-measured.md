## Important Context

`uv run` RESOLVES ITS PROJECT FROM THE PROCESS CWD, and that is the mechanism behind #909. `_ruff_format_dir` passed `--config <root>/pyproject.toml` explicitly, which is exactly what made it look root-derived; the config was never the ambient half. Any gzkit code shelling out to `uv run` against a tree it is not standing in has this bug shape.

A SUPPRESSED SUBPROCESS FAILURE IS THE OTHER HALF. `suppress(FileNotFoundError, TimeoutExpired, SubprocessError)` around the formatter meant a total failure to format was indistinguishable from success. The cwd binding is fixed; the suppression is unchanged and still hides a real failure from every caller.

A `uv`-UNBUILDABLE FIXTURE IS A LEGITIMATE TEST INSTRUMENT. The first version of the #909 property test used a benign temp project, `uv run` succeeded from both directions, and it passed while discriminating nothing. A fixture naming a build backend that does not exist with `requires = []` fails locally in ~30ms, offline. Reach for it whenever a test needs the adopter-tree condition rather than the gzkit-repo condition.

THE #908 HYPOTHESIS WAS WRONG IN A WAY THAT MATTERED. It predicted "a second renderer for the same artifact"; the mirrors were MISSING, not divergent — one renderer run too early. Two diagnoses, two different fixes. Read the 58 error messages before trusting an issue's own theory.

`iterdir()` ORDER IS THE FILESYSTEM'S CHOICE. `test_init_creates_src_package` indexed the first entry and was correct only while `src/` held one. Making init leave a synced tree added the nested `src/AGENTS.md` and the test began passing at random. Any first-entry-of-iterdir in this repo is a latent flake waiting for a second file.

A GREEN TEST CAN BE GREEN BECAUSE THE SURFACE IS ABSENT. `test_readiness_audit_passes_for_initialized_repository` passed because the reachability audit returns early when the instructions directory does not exist. Rendering the mirrors made it fail with 33 findings that were always true. This is the same shape GHI #891 exposed for #908 — worth checking wherever a gate passes on a scaffolded tree.

THE #906 SATURATION POINT IS THE RESULT, NOT THE 18.6%. Four Behave shards buy the same gate time as eight; past roughly 34s Behave stops being the critical path and further shards are pure contention with `Test`. Any future sharding work should start at 4.

BEHAVE'S IN-GATE COST IS NOT ITS STANDALONE COST. 29.33s standalone, 47-49s inside `gz check`. Use the in-gate figure as the denominator for any gate-speed claim; the standalone number overstates the available gain by more than half.

THE `verifier-pipe-gate` HOOK PARSES ONLY THE FIRST STATEMENT. A heredoc followed by a piped verifier trips it even with `set -o pipefail` first. Split the heredoc write and the piped run into separate calls.

DO NOT `git stash --keep-index` TO GET A BASELINE. It keeps the working tree as-is, so it does not produce one, and popping it against a since-edited file yields an add/add conflict. Reason from the code or use a worktree.

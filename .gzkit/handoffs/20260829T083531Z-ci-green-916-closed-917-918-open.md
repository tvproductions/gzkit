## Important Context

**Patching a module attribute named subprocess.run is NOT module-local.** A module's `subprocess` name references the singleton subprocess module, so patching its `run` attribute rebinds it process-wide. The dotted path reads like scoping and provides none. Contrast the target `gzkit.commands.patch_release.run_exec`, which IS local because an import-bound name is a fresh binding in the importing module. This is the whole mechanism of the outage and is easy to misread in either direction.

**The class fix covers the PATCHER arm only, and the close comment says so.** Stopping all patchers in `features/environment.py` handles every started patcher, but two causes in the same family remain uncovered by that mechanism: a step mutating `os.environ` (handled today only because the ONE variable any step assigns is restored by name), and a step rebinding an attribute directly without mock (no instance exists today; a grep over the step modules finds none).

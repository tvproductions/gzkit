THIRD: the obvious fix for #713 was wrong three times over, and each wrong turn was only visible after the previous one was built. There was no advisory channel to render (four audits, four invented prefixes, none recognizable); 'a passing step's stderr' is not the channel because unittest writes its whole summary there; and the test step's stderr carries advisory-marked lines from fixtures, so the naive fix reported 28 simulated findings about temp directories as findings about this repository. FOURTH: the fix for that third problem was initially attempted in the wrong layer. Four test files deep into capturing fixture stderr, the tell was that leaks kept appearing in modules I had not touched. Test hygiene was not the defect; treating a test runner's output as a source of project findings was. Reframed, it is one predicate reading the command the step actually ran, and it is immune to future tests leaking again in a way the test-by-test fix never would have been.

# Token-Block Discipline (gzkit)

> **Rule version:** `0.8.0` — diet pass under GHI #921: the landed-staging notes (OBPI-0.0.41-02/-03/-04), the blocklist-to-default-DENY history and the pre-GHI #764 section-misfiling record lifted to [Rule Version History](../../docs/governance/rule-version-history.md#token-block-disciplinemd); the stale `Generated by OBPI-0.0.41-01 — do not edit` marker removed (the rule has been edited seven times since). Binding rules unchanged.

## Doctrine Foundation

**A token cannot be surrendered without a register entry.** Memory is not evidence; lock release is coupled to a handoff document or an explicit abandoned/reaped exchange record. Lineage, vocabulary and rationale: [`docs/governance/token-block-doctrine.md`](../../docs/governance/token-block-doctrine.md).

## Sub-Invariant 1: Auditable Abandon Categories

`obpi_lock_release_cmd` and `lock_manager.release_lock()` accept `--abandon <category>:<reason>`; it writes a degenerate exchange record (`abandoned: true`, category and reason) and releases. Without it, release requires an existing register entry (§ Sub-Invariant 5).

The abandon categories are closed: `network_loss`, `external_blocker`, `wrong_obpi_claimed`, `tool_failure`, plus `reaping` (§ Sub-Invariant 3). A new category needs ADR-backed rationale and a checklist item in the next maintenance ADR; `parse_abandon_spec` rejects an unregistered category at parse time, and free-text-only abandonment (`--abandon "session timeout"`) is refused.

## Sub-Invariant 2: Register-Entry Minimum Information

A register entry is valid only with all four, on the structured channel `gz validate --lock-exchange-coupling` reads (free-body prose does not satisfy it):

1. frontmatter `last_lock_event_timestamp` — the matching `obpi_lock_claimed` event this handoff concludes;
2. frontmatter `last_commit_sha` — HEAD at handoff creation;
3. a `## Decisions Made` body section — the traversal's decisions in prose (deferred X, blocked by Y, completed Z, transferred to Q);
4. frontmatter `branch`.

An entry lacking any of them fails the validator (exit 3).

## Sub-Invariant 3: Reaping Register-Entry Rule

When `lock_manager.reap_expired_locks()` finds a lock past TTL (§ Sub-Invariant 4), the reaping agent writes a degenerate exchange record first — frontmatter `abandoned: true`, `category: reaping`, `abandoned_by`, `abandoned_at`, `previous_agent`; body stating the reason (TTL exceeded, last activity) and the claim event's commit SHA and branch — then releases with `--abandon reaping:<reason>`. The release fails closed if the record does not exist; the ledger's `obpi_lock_released` cites its `handoff_path`, and the ledger entry states that the record was created before the reap. Reaping is not an exception to the invariant; it is the same rule under degenerate circumstances.

## Sub-Invariant 4: TTL Canon and Reaping Discipline

The default TTL is 24 hours (`lock_manager.py`). At 50 % the SessionStart hook warns to console and ledger ("OBPI lock held by <agent> for >12h; consider `gz-session-handoff`"); at 100 % the next SessionStart hook reaps per § Sub-Invariant 3. A reaped lock may be re-claimed by any agent; the ledger trail is the audit evidence. Any agent starting a session is authorized to reap an expired lock; reaping before expiry requires the operator's explicit `--force`.

## Sub-Invariant 5: Release Fail-Closed Precondition

`obpi_lock_release_cmd` and `lock_manager.release_lock()` refuse to release unless either:

1. a handoff document exists whose frontmatter timestamp is later than the matching `obpi_lock_claimed` event, does NOT carry `abandoned: true`, has `mode: CREATE`, and carries the four § Sub-Invariant 2 fields; or
2. the caller passes `--abandon <category>:<reason>` (§ Sub-Invariants 1 and 3).

The admit predicate `is_exchange_register_entry` is default-DENY: it accepts only the shape an exchange writer emits, so `CHECKPOINT`, `RESUME` and any later mode are refused without enumeration (GHI #763). **Binding:** a `CHECKPOINT` handoff never satisfies token surrender — a checkpoint records a pause without departing, so accepting it would let a bookmark discharge a release the session never performed (GHI #756). Location is the first fence (session documents do not enter `.gzkit/locks/exchange/`); the predicate is the second; `gz validate --lock-exchange-coupling` replays the ledger and fails closed on any `obpi_lock_released` event without a valid `handoff_path` or whose entry violates § Sub-Invariant 2.

## Sub-Invariant 6: Completion Surrender Is Mechanical

`gz obpi complete` (and the pipeline sync stage that calls it) is the token-block exit edge: on success it writes a full completion handoff as the register entry, auto-drafted from completion evidence, and — if a lock is held — deletes it and emits `obpi_lock_released` citing that `handoff_path`. No operator prompt, no manual `gz obpi lock release`. The handoff is written before the delete (if it cannot be written the lock is left for TTL reaping) and after completion's transaction commits. § Sub-Invariant 5 still governs mid-traversal surrender (GHI #619).

## Sub-Invariant 7: The Exchange Record Carries an Observation Report

A completion exchange record carries, beyond the fact of surrender, an observation report of the traversal — what was learned, the residual for the next occupant, the artifacts produced. Operator canon, verbatim (2026-08-06, `invariant` tier): *"exchange (noting block vacation and an observation report of what happened)"*. Each content kind lands in the section whose tense it matches:

| Section | Content kind | Inlet |
|---|---|---|
| Current State Summary | the surrender fact and what the traversal did | `implementation_summary` |
| Important Context | what the traversal learned about the block | `observation` |
| Decisions Made | the operator's verbatim Gate-5 attestation | `attestation_text` |
| Immediate Next Steps | the residual for the next occupant | `residual` |
| Pending Work / Open Loops | open loops at surrender | `open_loops` |
| Verification Checklist | the proof the traversal produced | `key_proof` |
| Evidence / Artifacts | artifacts actually produced | `artifacts` |

The inlets are optional by design — requiring one would re-create the stranded locks GHI #619 removed — and `gz obpi complete` sources `observation` from the brief's `### Value Narrative` and `open_loops` from its `## Tracked Defects`. Content goes in the section it belongs to, not the one it fits: a section that emits byte-identical text across every record has no channel (GHI #764).

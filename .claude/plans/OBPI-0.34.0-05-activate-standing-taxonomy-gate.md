# Plan — OBPI-0.34.0-05-activate-standing-taxonomy-gate

**OBPI:** `OBPI-0.34.0-05-activate-standing-taxonomy-gate`
**Parent ADR:** `ADR-0.34.0-foundation-sunset`
**Lane:** Heavy · **Sensitivity:** security

## Context

Final act of the Foundation Sunset. OBPI-04 left the tree terminal (51
grandfathered manifest entries, 23 foundations demoted to pool,
`gz validate --taxonomy` exits 0 standalone). This OBPI makes closure
*permanent* by wiring `--taxonomy` into `gz check`, and seals the two
`adr_created` ledger ingress points so a hand-placed `kind: foundation`
package cannot enter Layer-2 un-guarded (GHI #706).

Parent ADR § Decision (verbatim, checklist item 5): "Activate the permanent
closure gate: run register-adrs to reconcile the Layer-3 status index after
the demotions; wire the --taxonomy gate (closed-kind + terminal-partition
assertions) into gz check as the LAST act (wiring equals a terminal tree, so
it lands green; anti-staging-flag doctrine forbids wiring earlier over limbo
foundations). Seal the registration membrane in the same act..."

## Plan-Before-Exploration Disclosure (Step 6a)

**Destination-in-mind.** Before exploring I had already formed the approach:
mirror `run_adr_status_fresh_audit` for the new runner, append one tuple to
`_build_check_steps()` plus one `_STEP_GUARD_META` entry, and seat a
manifest-membership check in front of both `ledger.append(adr_created_event(...))`
call sites. Exploration confirmed rather than originated this shape — the brief
names the pattern explicitly ("sibling of `run_adr_status_fresh_audit`").

**Rejected alternatives.**
1. *Put the membrane helper in `models/foundation_grandfather.py`* (its natural
   domain home, next to `load_manifest`). Rejected: not in the brief's Allowed
   Paths. Fixing the brief instead of the code was considered and rejected too —
   the allowlist is correct here; `register.py` is a legitimate host and the
   helper is guard logic, not model logic.
2. *Guard on `kind: foundation` alone.* Rejected explicitly by Requirement 5 —
   it would refuse all 74 grandfathered packages and contradict the closure it
   enforces. The check must be manifest-membership-aware.
3. *Wire the step earlier and gate it behind a staging flag until the tree went
   terminal.* Rejected by anti-staging-flag doctrine; REQ-05-03 exists precisely
   to assert this was not done.
4. *Assert REQ-02's "gz check exits 0" by running the full `gz check` aggregate
   in-test.* Rejected: multi-minute subprocess, and it would make the unit test a
   duplicate of CI. Assert step membership structurally and the taxonomy runner's
   real exit separately.

## Steps

1. **Reconcile the Layer-3 status index (REQ-01).**
   Run `uv run gz register-adrs` to regenerate
   `docs/governance/GovZero/adr-status.md` against the post-demotion tree.
   Confirm `uv run gz validate --adr-status-fresh` exits 0.
   RED first: assert freshness in a `@covers(REQ-0.34.0-05-01)` test.

2. **Add `run_taxonomy_audit` (REQ-02 support).**
   In `src/gzkit/quality.py`, sibling of `run_adr_status_fresh_audit`:
   `return run_command("uv run gz validate --taxonomy", cwd=project_root)`.
   Docstring names the closed-kind + terminal-partition assertions it wraps.

3. **Wire the step as the LAST tuple (REQ-02, REQ-03).**
   In `src/gzkit/commands/quality.py`: import `run_taxonomy_audit` into
   `_build_check_steps()`, append `("ADR taxonomy", run_taxonomy_audit)` after
   `("Enforcement floor", run_enforcement_floor_audit)`, and add
   `"ADR taxonomy": ("taxonomy", _mx_levels.ERROR)` to `_STEP_GUARD_META`.
   No flag guard, no conditional — direct tuple binding (REQ-03).
   RED first per behavior: membership test, then ordering/binding test.

4. **Seal the registration membrane (REQ-04).**
   In `src/gzkit/commands/register.py`, add a helper that returns True when an
   on-disk ADR package declares `kind: foundation` AND its id is absent from
   `data/foundation_grandfather.json` (via the existing
   `models.foundation_grandfather.load_manifest`). Seat it in front of
   `ledger.append(adr_created_event(...))` in `_emit_adr_created_or_skip`;
   refuse (no event appended) with three-part guardrail prose mirroring
   OBPI-02's authoring-door guards. Import the same helper into
   `src/gzkit/commands/init_cmd.py` and seat it at the first-run ingress
   (~line 867). Manifest members still book normally.
   RED first per ingress: assert no `adr_created` event for an
   un-grandfathered foundation package; assert a manifest member still books.

5. **Run the brief's verification block** (all ten commands) and the RED
   falsifiability witness (`gz arb red`) for each of the four BEHAVIOR REQs.

## Notes

- **Denied paths stay untouched:** `taxonomy.py` (OBPI-01/03 authored the
  assertions; this OBPI only wires them), `sunset_migrate.py` /
  `foundation_grandfather.json` (OBPI-04 data), `plan.py` /
  `adr_promote.py` (OBPI-02 doors), `src/gzkit/flags/**` (never).
- **Ordering constraint:** the gate is wired only after step 1 confirms the
  tree is terminal, so `gz check` lands green on first run.
- **Security sensitivity:** `src/gzkit/quality.py` is a registered
  `subprocess_user_input` surface. The added runner uses the same
  `run_command(...)` template as every sibling audit — no new subprocess
  shape, no user-interpolated argument.
